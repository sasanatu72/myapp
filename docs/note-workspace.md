# ノート編集とローカル確認

ノートタブでは従来のカード形式の一覧・検索・並び替えを表示します。カードまたは＋ボタンを押すと編集画面へ進みます。編集画面は左にノート一覧、右に編集領域を表示し、左上の戻るボタンで保存して一覧に戻ります。狭い画面では編集画面の一覧ボタンからノートを切り替えます。書式付きノートも一覧では本文のテキストを表示・検索します。

本文の標準サイズは14px、書式ボタンには薄い枠線を付けています。用紙は従来と同じ最大幅800pxで、A4（210:297）の比率を最小の高さとして使い、内容が増えると下へ伸びます。高さを固定せず、用紙全体をスクロールします。実ブラウザーで幅800px・基本高さ約1131px、91行の本文で高さ約2438pxまで拡張することを確認しました。

本文にはブラウザー標準のcontenteditableをFlutterのHtmlElementViewで埋め込みます。以前のFlutter TextFieldの大きなscrollPadding/contentPaddingを取り除き、IMEが実際の文字位置を使える構成にしました。入力中や保存応答のたびにDOMを書き直しません。変換中は自動保存と書式操作を待機します。OSが表示する候補ウィンドウの最終的な位置は、各ブラウザーと日本語IMEで確認してください。

DOM上で編集欄やツールバーにフォーカスがある間は専用のFlutter FocusNodeへ同期し、Enter・矢印キーなどをFlutterのショートカットに消費させず、ブラウザーの標準編集へ渡します。箇条書き・番号付きリスト内ではTabで階層を下げ、Shift+Tabで上げます。内容がある項目のEnterは同じ階層の次の項目を作り、空の項目のEnterは階層を1つ上げます。最上位の空項目ではリストを終了します。IME変換中のEnterは変換確定に使います。

見出し・太字・斜体・下線・取り消し線・箇条書き・番号付きリスト・インデント・引用・コード・元に戻す/やり直しを利用できます。外部からの貼り付けはプレーンテキストです。保存したHTMLは許可した文書要素だけを復元し、リンク・画像・スクリプト・任意の属性は復元しません。

既存のnotes.content（TEXT）に、書式付きノートはバージョン識別子・HTML・検索用テキストを含むJSONとして保存します。既存のプレーンテキストは変更せず読み取れます。DBスキーマ変更は不要です。旧フロントエンドは新しい書式付きデータを解釈できないため、フロントエンドだけ旧版に戻す場合は注意してください。Android/iOSのネイティブビルドでは従来のテキスト編集を利用し、書式付き本文は書式を失わないよう読み取り専用にしています。スマートフォンのWeb版では書式編集ができます。

保存処理は直列化し、保存中に続けて入力した内容も保存します。ノート切替・機能タブ切替・設定への移動では保存完了を待ち、失敗時は下書きを残して移動を止めます。未保存のままブラウザーを離れる場合は、ブラウザーの確認を利用します（ブラウザーによって表示条件が異なります）。

## ローカル起動（PowerShell、別々のターミナル）

```powershell
cd backend
.\.venv\Scripts\python.exe run_local.py --demo
```

```powershell
cd frontend
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 8080 --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

http://127.0.0.1:8080/ を開き、ローカル専用の `demo@example.com` / `example` でログインします。APIは http://127.0.0.1:8000/docs です。`run_local.py` は接続先を `backend/.local/life_custom.db` に固定し、RenderのDBに接続しません。初回の仮想環境は `python -m venv .venv`、依存関係は `.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt` で準備します。

## 確認項目

今回の確認では、一覧→編集→保存して戻る遷移、保存失敗時の保持、保存処理、IME変換中の待機、デスクトップ/スマートフォン画面のFlutterテスト10件、変更したDartファイルの静的解析、Webリリースビルドを実行しています。ローカルのブラウザーでも日本語入力、改行・矢印キー、Tab/Shift+Tab、空項目でのEnter、用紙の縦方向拡張、自動保存、ノート切替後の書式復元を確認しています。

起動確認時に既存の `/events` → `/events/` リダイレクトでブラウザーの取得が失敗したため、既存の `/events/` に加えて `/events` でも直接応答する互換ルートを追加しています。

`test/browser/note_document_editor_browser.dart` にはDOM復元・変換イベント・HTMLの制限を検証するブラウザー用テストがあります。この環境ではChrome/Edgeともテストランナーの初期読み込み待ちが続き、完走は確認できていません。実ブラウザー上でOSのIME候補ウィンドウを表示するテストは行えていません。

```powershell
flutter test --no-pub test/note_workspace_test.dart
flutter test --platform chrome --no-pub test/browser/note_document_editor_browser.dart
```

- 日本語を本文の先頭・途中・末尾に入力し、変換中・スクロール後・ウィンドウサイズ変更後の候補位置を確認する。
- 書式を指定して入力し、自動保存後に別ノートへ切り替え、再度開いて書式を確認する。
- 通信が遅い状態でも入力を続け、最後の変更まで保存されることを確認する。
- 保存失敗時は移動が止まり、再試行できることを確認する。
- 従来のプレーンテキスト、日本語の検索、ノート作成・削除、狭い画面とダークテーマを確認する。
